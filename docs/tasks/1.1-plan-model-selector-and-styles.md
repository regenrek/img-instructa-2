## Plan v1.1: Model Selector & Predefined Styles (Production-Ready)

### Overview

This refines the original plan with production-hardening details: typed URL state, strict validation, SSR/hydration safety, accessibility, error handling, and explicit tests. It remains incremental and compatible with the current UI and server function.

---

### 1) Architecture & Types

- **Model registry** (`src/lib/config/models.ts`)
  - Provide `AVAILABLE_MODELS` and `DEFAULT_MODEL_ID` (as already planned).
  - Add helpers:
    - `getModelConfig(modelId: string): ModelConfig | undefined`
    - `getAllowedModelIds(): readonly string[]`
  - Derive runtime zod schema: `z.enum(getAllowedModelIds() as [string, ...string[]])`.
  - Enforce max steps and supported sizes via config (clamp or reject).

- **Styles config** (`src/lib/config/styles.ts`)
  - Keep `PREDEFINED_STYLES`, `DEFAULT_STYLE_ID`, and `applyStyle` pure (no side effects).
  - Add helper: `getAllowedStyleIds(): readonly string[]` for validation and typed search.

- **Types** (`src/lib/types/fal.ts`)
  - Define a normalized output type used by UI across models:
    - `{ images: Array<{ url: string; width: number; height: number }>, seed?: string | number, timings?: { totalMs?: number } }`.
  - Optionally add per-model input types and a union if needed.

---

### 2) URL State (Typed Search Params)

- **Route search schema** (`src/routes/(app)/image-gen/route.tsx`)
  - Add typed search for model/style with safe defaults and fallback:

```ts
// Pseudocode sketch
const searchSchema = z.object({
  model: z.enum(getAllowedModelIds() as [string, ...string[]]).default(DEFAULT_MODEL_ID),
  style: z.enum(getAllowedStyleIds() as [string, ...string[]]).default(DEFAULT_STYLE_ID),
});

export const Route = createFileRoute('/(app)/image-gen')({
  validateSearch: (search) => searchSchema.parse(search),
});
```

- **Usage in components** (`ImagePromptForm`, `AiImageGenerator`)
  - Read with `Route.useSearch()`; update via `navigate({ search })`.
  - Form submit includes `model_id`/`style_id` from search (single source of truth).

Benefits: Shareable URLs, SSR-friendly, no `useEffect` data-fetch pattern drift.

---

### 3) Server Function: Validation & Normalization

- **Input schema** (`src/server/function/aiImage.generate.ts`)
  - `model_id`: zod enum derived from registry (see above).
  - `style_id`: zod enum derived from styles; default applied server-side.
  - Prompt constraints: `prompt` min/max, `negative_prompt` max.
  - Steps and size: clamp to config (`maxSteps`, `supportedSizes`).

- **Model-specific shaping**
  - Derive `ModelConfig` → merge defaults.
  - Create `enforceModelParams(input, modelConfig)` that:
    - Applies defaults
    - Removes unsupported fields
    - Clamps ranges (steps, sizes)
    - Returns final payload for fal.

- **Styles application**
  - Apply `applyStyle` before shaping payload.
  - If a style has `modelSpecific` entries, merge safely for those models.

- **Output normalization**
  - Map fal outputs to the normalized structure consumed by the UI.
  - Include optional `timings` if available; ignore model-specific extras in UI layer.

- **Error handling**
  - Map zod errors to user-friendly messages.
  - For invalid `model_id`/`style_id`, reject and suggest defaults in message.

---

### 4) UI & Accessibility

- **Select component** (`src/components/ui/select.tsx`)
  - Implement using `@radix-ui/react-select` with keyboard navigation and ARIA.
  - Provide controlled `value`, `onValueChange`, and disabled state while generating.
  - Ensure visible labels (`Label` + `htmlFor`) and descriptions for both Model and Style.

- **Form updates** (`src/components/image-prompt-form.tsx`)
  - Model select at top; Style select below prompt.
  - When model/style changes, reset any in-flight progress using `startTransition`.
  - Disable submit while required fields invalid or generation in progress.

---

### 5) SSR, Hydration, and Performance

- Avoid fetching in `useEffect`; use route loaders if needed.
- Wrap synchronous updates that may suspend during hydration with `startTransition`.
- Do not render `isPending` during initial hydration.
- Keep interactions snappy; avoid first-click spinner (defer non-critical work).

### 9) Acceptance Criteria

- Model/style are reflected in the URL and survive refresh/share.
- Invalid model/style in URL are rejected with clear UI and reset to defaults.
- Switching model clamps steps and size to supported ranges without crash.
- At least two models verified; styles applied to prompt and negative prompt.
- UI controls accessible via keyboard and screen readers.
- All tests pass with `vitest --run`.

---

### 10) Rollout & Backwards Compatibility

- Default to `DEFAULT_MODEL_ID` and `DEFAULT_STYLE_ID` when search empty.
- Gracefully reset invalid search params to defaults with a one-time notice.
- No breaking changes to existing prompt submission API.
