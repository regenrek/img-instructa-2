# Plan v1.1 — Model Selector & Predefined Styles (Production-Ready)

This revision tightens the original plan to align with our Ruler guidelines (no data/state derivation in effects, URL as state, server work on the server) and adds missing production concerns: typed search params, accessibility, cancellation, testing, and rollout.

## Goals
- Model selection across multiple fal.ai generators with safe defaults and guardrails.
- Predefined style presets that are composable and model-aware.
- Shareable, restorable state via URL (no app state hidden in effects).
- Solid UX: accessible controls, clear errors, predictable hydration.

## Non‑Goals
- Style gallery thumbnails generation.
- Full model capability matrix UI (basic constraints only).

## Constraints (Project)
- Use server functions for mutations; avoid client effects for fetching.
- Keep state in URL using typed search params.
- Use `pnpm`; do not touch `.env`, only `.env.example`.
- All route files TypeScript React (`.tsx`).

## Architecture Decisions
- Server‑first generation via `createServerFn(...).handler(...)` in `src/server/function/aiImage.generate.ts`.
- UI state in URL: `model` and `style` search params managed via `validateSearch` → `Route.useSearch` → `navigate`.
- No fetching/deriving app state in `useEffect`. Effects limited to DOM/analytics only.
- Prompt/style composition done synchronously during render/submit; no suspense during hydration.

## Data Model & Types

### Model Registry
File: `src/lib/config/models.ts`
- Export `ModelId` as a string union derived from `AVAILABLE_MODELS`.
- Each model defines: `id`, `name`, `description`, `category`, `supportsStyles`, `defaultParams`, `supportedSizes`, `maxSteps`, and optional `capabilities` (e.g., requires square, supports `guidance_scale`).
- Provide a `getModel(id: ModelId)` helper and `DEFAULT_MODEL_ID`.

### Styles Registry
File: `src/lib/config/styles.ts`
- Export `StyleId` union from `PREDEFINED_STYLES`.
- Style includes `promptPrefix`, `promptSuffix`, `negativePromptAdditions`, and `modelSpecific` overrides keyed by `ModelId`.
- Export `applyStyle(userPrompt, styleId, modelId, currentNegativePrompt)`; ensure pure, deterministic output.

### Shared Types
File: `src/lib/types/fal.ts`
- `ImageGenerationInput` covers common fields.
- Narrowing helpers per model: type guards to map to model‑specific input.
- `ModelOutput` normalized shape: `{ images: Array<{ url: string; width: number; height: number }>; seed?: number; meta?: Record<string, unknown> }`.

## URL State (Typed Search Params)

Route file hosting the generator (e.g., `src/routes/generator.tsx`):
- `validateSearch` schema: `{ model: z.enum(ModelIds).optional(), style: z.enum(StyleIds).optional(), steps?: z.number().int().min(1).max(max), w?: z.number(), h?: z.number() }`.
- Use `Route.useSearch()` to read; seed local UI from search only on initial render (no effects needed).
- Update via `navigate({ search: (prev) => ({ ...prev, model, style }) })` on user interactions. Avoid rendering `isPending` during hydration.

Benefits:
- Deep‑linkable and restorable sessions.
- No hidden client state; complies with Rule #3.

## Server Function

File: `src/server/function/aiImage.generate.ts`
- Input schema: `{ model_id: z.string(), prompt: z.string().min(1).max(500), negative_prompt?: z.string().max(500), steps?: z.number().int().min(1).max(50), width?: z.number(), height?: z.number(), seed?: z.number() }`.
- Map `model_id` → model config; validate requested params against model `capabilities` and `supportedSizes`. If invalid, coerce to defaults or return a 400 with actionable message.
- Apply styles: `applyStyle(prompt, style_id ?? DEFAULT_STYLE_ID, model_id, negative_prompt)` and then model‑specific overrides.
- Call fal.ai via `subscribeWithProgress<ModelOutput>(model_id, input)`; normalize to `ModelOutput`.
- Cancellation: accept a client‑provided `requestId`; ignore late responses if superseded. Optionally expose a `cancel` server function if upstream supports it.
- Do not write to client storage during SSR.

Form usage patterns supported:
- Programmatic: `await serverFn({ ... })`.
- Declarative: `<form action={serverFn.url}>` with progressive enhancement.

## UI Components

### Selects
File: `src/components/ui/select.tsx` (Radix or equivalent)
- Keyboard accessible, labelled, controlled component.
- Avoid suspense during hydration; components are purely client‑side UI.

### Prompt Form
File: `src/components/image-prompt-form.tsx`
- Controlled fields: `prompt`, `negative_prompt`, `model_id`, `style_id`, `steps`, `size`.
- No `useEffect` to sync with URL. On change, call `navigate({ search })`.
- Guard UI based on model capabilities (disable unsupported options).

### Main Container
File: `src/components/ai-image-generator.tsx`
- Sources initial values from `Route.useSearch()` and config defaults.
- Submits to server function; displays streaming progress.
- Race safety: show the latest `requestId` only.

## Error & Empty States
- Invalid model/style → show inline field error and fallback to defaults.
- Generation failure → readable message and “Try again” with preserved search params.
- Unsupported size/steps for model → disable options with tooltip.
- Network/cancellation → gracefully stop progress UI.

---

## Accessibility & UX
- Labels and `aria-describedby` for selects; ensure contrast and focus rings.
- Loading states avoid layout shift; do not render pending UI that would suspend during hydration.
- Keyboard shortcuts: `/` focuses prompt; `Cmd+Enter` generates.

---

## Telemetry (optional)
- Fire analytics on generation submitted/succeeded/failed with `model_id`, `style_id` (no PII).
- Use a tiny effect for analytics only; never derive app state.

## Testing & QA

### Unit
- `applyStyle` pure function tests (prompt/negative prompt composition, modelSpecific overrides).
- Model registry guards (invalid id throws; defaults applied).

### Integration
- Server function schema validation and normalization snapshots.
- Model‑specific parameter mapping.

### E2E (Playwright)
- Deep link restoring `?model=...&style=...`.
- Switch model adjusts available sizes and step bounds.
- Generate flow happy path and cancellation (new request preempts previous).
